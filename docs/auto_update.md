# SmartStore Windows Updates

SmartStore checks the public GitHub Releases API for the latest stable release
of the configured repository. Update configuration is in
`lib/config/update_environment.dart` (`githubOwner` and `githubRepository`).
The current repository is `ozodbek9o9/smartstore`.

The application performs one check at startup. It does not block startup on a
network error or a missing release. A successful check is cached for six hours
within the running process. GitHub's unauthenticated API rate limit is normally
60 requests per hour per IP; a newer release also requires one checksum-asset
request.

## First Installation

Give new customers the latest `SmartStore-Setup-x.y.z.exe` from GitHub Releases,
not `smart_store.exe` alone. The installer contains the full Flutter runtime
bundle, creates a Start menu shortcut, and optionally creates a desktop
shortcut. An older installer still checks for updates at startup and offers
the newer release.

Install Inno Setup 6 on the build computer. Set both the pubspec package version
and the build-time semantic version, then create the installer:

```powershell
# Example for release 1.1.0; set version: 1.1.0+2 in pubspec.yaml first.
flutter build windows --release --dart-define=SMARTSTORE_VERSION=1.1.0
.\tools\build_installer.ps1 -Version 1.1.0
```

This creates:

- `dist/SmartStore-Setup-1.1.0.exe`
- `dist/SmartStore-Setup-1.1.0.exe.sha256`

The setup is per-user and installs under `%LOCALAPPDATA%\Programs\SmartStore`.
App preferences and customer data are stored outside the install directory, so
an update does not replace them. Unsigned installers can trigger a Windows
SmartScreen unknown-publisher warning.

## Publish a Release

1. Update `version:` in `pubspec.yaml`, for example `1.1.0+2`.
2. Build with the exact `1.1.0` semantic version using the commands above.
3. In GitHub, create a **published stable release** tagged `v1.1.0`. Do not mark
  it as a draft or prerelease.
4. Attach both generated files without renaming them:
  `SmartStore-Setup-1.1.0.exe` and `SmartStore-Setup-1.1.0.exe.sha256`.
5. Add release notes to the GitHub release description. The updater displays
  those notes in the update dialog.

The sidecar checksum is generated by `build_installer.ps1`; the updater fetches
it from the same release and verifies the downloaded installer before launch.
Keep the repository public so the unauthenticated Releases API and assets are
downloadable. Never put a GitHub token in the Flutter application.

If the repository has no published stable release yet, publish the initial
installer and checksum as release `v1.0.0`. Until a stable release with both
assets exists, startup checks safely return without showing an update.

## Update Flow

During the splash screen, SmartStore requests
`GET /repos/{owner}/{repository}/releases/latest`. It validates the strict
semantic version, requires the version-matching installer and `.sha256` asset,
and accepts download URLs only from the configured repository's GitHub release
path. Network failures, GitHub 404/rate limits, malformed releases, and missing
assets do not prevent normal startup.

If the release is newer, the same centered dialog appears after startup. Choosing
**Later** leaves the app running and keeps the AppBar update icon available to
reopen that dialog. **Update now** downloads to a temporary directory, displays
progress, verifies the size and SHA-256, then starts the Inno Setup installer
silently and exits SmartStore. Inno Setup closes the old process if needed,
updates the files in place, preserves data outside the install directory, and
launches the updated app. A failed or cancelled download leaves the existing
installation untouched and allows retry.

## Test 1.0.0 to 1.1.0

1. Install a `1.0.0` build created with
  `--dart-define=SMARTSTORE_VERSION=1.0.0`.
2. Publish a stable GitHub release `v1.1.0` with the matching installer and
  checksum sidecar.
3. Start the installed `1.0.0` build while online. The splash checks GitHub and
  the update dialog should show `1.0.0` and `1.1.0` plus the release notes.
4. Choose **Later** to verify the AppBar icon reopens the same dialog. Choose
  **Update now** to test progress, cancellation/retry, installation, and
  relaunch.
5. Start SmartStore again. The update icon should be absent because the
  installed and latest versions match.

Automated unit tests cover semantic version ordering, trusted asset validation,
no-release responses, checksum retrieval, and the already-current case. The
actual Inno upgrade/relaunch should also be smoke-tested on a clean Windows x64
account before distributing a release.
